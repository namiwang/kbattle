- Faults (tested): an upstream 429 → `429 {"error":"rate limited"}`. Any other failure → `502 {"error":"doer backend failed"}`. Never a 500 or a stack, and no retries in the Worker (§5.5).
- Types: `@cf/cloudflare/clef-flash` is not in the `AiModels` map of `@cloudflare/workers-types` 5.20261019.1. So `Ai.run` takes its unknown-model overload (`Promise<Record<string, unknown>>`) and needs no cast. `test/clef.test.ts` pins this with `expectTypeOf`.

The status is only recorded on the binding, as `lastRequestHttpStatusCode`. The Worker reads it there to tell a 429 from other failures, and never has an upstream `Retry-After` to forward.

## Deviations from the plan

- `routes/decide.ts` does not swap out the mock. `DOER_BACKEND` (`[vars]`) chooses: `"mock"` by default, `"clef"` under `[env.live]`, which also binds `AI`. Any other value, or none, gets the mock. Reason: I-001; `wrangler dev` cannot start with an `[ai]` binding and no token.
- DESIGN.md §9, §5.4 and row 34 are not edited. That waits for real numbers.
- 429 detection: the brief assumed the binding's error carries a status, and it does not (see Evidence). An error's own `status` and `retryAfter` win when present (tested). Otherwise the binding's `lastRequestHttpStatusCode` is used (tested with a fake that records it the way workerd does).
- The report logic lives in `worker/scripts/measure-report.ts` so it can be unit-tested; `measure.ts` is the HTTP loop. `--n` above 500 is refused (the plan's budget).
- The scripts typecheck under the worker tsconfig (workers-types, where `process` is `any`). A local `declare const process` types the three members they use, so no `@types/node` and no second tsconfig were added.

## Carry-forward risks

- v3.1 / v4.4: `lastRequestHttpStatusCode` is undocumented and shared within an isolate. Concurrent calls can overwrite it, and a failure before any HTTP response keeps the previous call's status. Worst case, a 429 is reported as a 502 or the reverse. If step 6 shows rate-limit messages behind 502s, fix the mapping then.
- v3.1: no `Retry-After` reaches the browser through the binding, so the client's own capped exponential backoff (§5.5) is the only one. If a source ever appears, cross-origin dev needs `access-control-expose-headers: retry-after`.
- v4.5: `wrangler deploy` without `--env` now warns that several environments exist. Deploy with `--env live` (Worker name `kbattle-live`), or rename.
- v4.4: I-010 (the content-type guard) is still open.
