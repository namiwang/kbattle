## Evidence

- SDK: `@anthropic-ai/sdk` 0.135.0 (`brain/package.json`, lockfile).
- Structured output: `messages.create` with `output_config: { effort: "low", format: { type: "json_schema", schema } }`. The schema comes from the SDK helper `zodOutputFormat(PlanSchema)`, which moves `minLength`/`maxLength` into description hints and adds `additionalProperties: false`. The reply goes through `PlanSchema.safeParse`. `messages.parse()` is not used: it throws on bad output and hides the refusal stop reason. Forced tool use was not needed.
- Request: model `THINKER_MODEL` (`claude-haiku-5-5`), `max_tokens` 600, `thinking: { type: "disabled" }`, `maxRetries: 0`, `dangerouslyAllowBrowser: true`.
- Fault mapping (tested): 401 and 403 → `auth`; 429 → `rate_limit`; any other error status → `server` (with `status`); `stop_reason: "refusal"` → `refusal`; non-JSON text, a JSON reply that fails the schema, a non-JSON body, or a 200 that is not a message → `invalid_output`; abort or connection timeout → `timeout`; failed connection → `network`.

## Live smoke (for Nami, with a key)

Budget: at most 50 calls and $0.01; the steps below make about 5 calls.

1. `pnpm install`, then `pnpm --filter web dev`; open `/spike-thinker.html` on the URL Vite prints. The browser needs a route to api.anthropic.com (the shell's proxy is not the browser's).
2. Paste the key. It is stored under localStorage `kbattle:v1:anthropic-key`.
3. Keep `max_tokens` at 600 and click **run spike** three times. Expect "Current plan" to show `{ text, scratchpad }`, and one log line per call: `ok in N ms: X in / Y out tokens, $Z`. Copy the three lines into "Measured" below.
4. Invalid JSON: set `max_tokens` to 10 and click **run spike**. Expect `invalid_output … (stop_reason: max_tokens); kept the last plan (§5.5)`, with the current plan unchanged. Set it back to 600.
5. 401: replace the key with `sk-ant-invalid` and click **run spike**. Expect a red `Stopped: auth 401 …` banner and a disabled button, with the plan kept. Paste the real key back; the banner clears.
6. Optional: DevTools → Network shows requests only to `https://api.anthropic.com/v1/messages`.
7. If step 3 fails, the log line says which way. `network: Connection error.` means CORS or the route. `server 400` naming `thinking`, `effort` or `output_config` means the API rejected the request shape. Record the message here.

## Deviations from the plan

- The page is `web/spike-thinker.html`, since Vite pages sit at the package root, not in `web/src/`. Its testable state is in `web/src/spike-thinker-state.ts`, with tests in `web/test/`.
- `web/vite.config.ts` uses `build.rolldownOptions.input`. Vite 8.3.4 marks `rollupOptions` deprecated.
- The page has a `max_tokens` field. Setting it to 10 gives the "deliberate invalid JSON" path on the real API: a cut-off reply.

## Carry-forward risks

- v3.5: `thinking: { type: "disabled" }` is valid for Haiku 5.5 at effort low to high only. Sonnet 5.5 rejects it (it wants `between_tools` or nothing), and so does Opus 5.5, at any effort. With either model every call would 400 → `server`, so the plan would silently never update. `brain/test/anthropic.test.ts` pins `THINKER_MODEL` to force a review.
- v3.4: `max_tokens` 600 is below what `Plan` allows (text up to 2,000 and scratchpad up to 4,000 characters). The harness prompt must ask for short output, or the reply is cut off → `invalid_output`.
- v3.2/v3.3: the SDK's default timeout is 10 minutes. Pass `signal: AbortSignal.timeout(…)`; an abort maps to `timeout`.
