## Deviations from the plan

- Structured output: the provider now sends `PlanReplySchema` (`PlanSchema` with 600 and 1,200 character limits) as its JSON schema, so the schema's length hints match what the harness asks for. Replies are still parsed with `PlanSchema` (2,000 and 4,000), so a reply that runs a little long is kept.
- The digest re-projects each sighting from where the agent stands and faces at the last note, so its bearings read like the ones in "Now". A bearing kept from the sighting would be relative to an old facing.
- The budget test also puts the plan at its 600-character cap, which the brief's scene list leaves out.
- `THINKER_TIMEOUT_MS` (20 s) lives in brain; core/constants.ts was outside this milestone's files.

## Carry-forward risks

- v3.3: the client returns `fatal` and the log input; stopping the match on a fatal error, keeping the last plan, and writing the `Thinker` event with `tick` and `requestedTick` are the orchestrator's job (p3-decisions D3). A test shows that such an event with the client's `input` passes `EventSchema`.
- v3.3: a digest noted only on doer ticks counts only the shots and near misses that fell on those ticks, since perception reports one tick's facts. hp, kills and sightings are exact. Call `reset()` when a call goes out; a failed call loses that window's counts.
- v3.4: the thinker gets no map. Principle 3 allows the static map; a compact obstacle list costs about 60 tokens per map, more than the 14 tokens of headroom left.
- v3.5: Opus 5.5 always thinks, and thinking counts toward `max_tokens` 600, so replies may be cut off (`invalid_output`). Haiku 5.5's tokenizer makes 1,800 characters of reply close to 600 tokens. Measure output tokens before picking the model.
- The v0.6 spike page stops only on `kind === "auth"`. It should test `error.fatal` so that 402 and 404 stop it too.
